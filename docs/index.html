Architecture

Layer-by-Layer Detection

Each site is probed through the full network stack. A failure is pinpointed to the exact layer where the connection breaks — giving you a precise verdict, not just “it’s not working.”

The tool compares your ISP’s resolver against Google’s 8.8.8.8 for DNS, then walks up through TCP → TLS → HTTP, stopping as soon as it finds the block.

LAYER 01
🌐
DNS Resolution

Compares the OS resolver’s response against Google’s 8.8.8.8 using a hand-rolled UDP DNS client (RFC 1035). Private IPs returned for public names = tampering.

dns_tampering
LAYER 02
🔗
TCP Handshake

Attempts a 3-way TCP handshake to port 443. A timeout or RST injection here means the connection is being actively blocked by a firewall or DPI box.

tcp_blocked
LAYER 03
🔒
TLS & SNI

Performs a full TLS handshake with the real hostname as the SNI field. A mid-handshake reset reveals SNI-based filtering (common in government censorship).

tls_interference
LAYER 04
📄
HTTP Request

Sends a HEAD / over the open TLS socket. HTTP 451 (Unavailable for Legal Reasons) is the clearest signal of government-mandated blocking.

http_blocked

Classification

Verdicts & What They Mean

Every probed site gets one of these verdicts. The combination across all sites determines whether it’s selective censorship or a full shutdown.

ok

All Clear

All four layers passed. The site is reachable without interference.

dns_tampering

DNS Manipulation

The ISP’s resolver returns different (often private) IPs compared to the control resolver at 8.8.8.8.

dns_failure

DNS Block

Control resolver succeeded but OS resolver returned NXDOMAIN — domain is being suppressed locally.

tcp_blocked

Firewall / DPI Block

TCP connection timed out or received a RST. A middlebox is dropping or resetting connections.

tls_interference

SNI-Based Filtering

TCP succeeded but TLS handshake was reset. The SNI field (hostname in TLS ClientHello) triggered blocking.

http_blocked

Legal Block (HTTP 451)

HTTP status 451 = “Unavailable For Legal Reasons”. The clearest signal of government-mandated censorship.

likely_outage

Internet Shutdown

When ≥80% of sites fail at DNS/TCP simultaneously with none succeeding — it’s a shutdown, not selective blocking.

Technical Highlights

What Makes This Different

🛠

Zero Dependencies

Written entirely using Python’s standard library. No pip install. No virtual environments. Runs anywhere Python runs.

📡

Hand-Rolled DNS Client

Implements UDP DNS queries from scratch per RFC 1035 — including name compression pointers — to bypass the OS resolver and compare results.

🔐

SNI-Aware TLS Probing

Sends the real hostname as the TLS SNI field to expose SNI-based filtering — a common technique used by internet shutdowns and censorship boxes.

🌐

Epidemic Routing

Simulates store-carry-forward messaging over short-range radio. Every meeting spreads copies — achieving 100% delivery even when no end-to-end path exists.

🎯

Precise Verdicts

Not just “it’s broken” — pinpoints the exact layer of failure. DNS tampering looks completely different from TCP blocking or TLS interference.

🚨

Outage vs. Censorship

When ≥80% of targets fail at the network layer, the tool switches from “selective blocking” to “likely_outage” — a shutdown fingerprint.

Get Started

Running the Tool

1
Blocking Detector

# Clone & run — no installs needed git clone https://github.com/ShivamRaghuvanshi2006/shutdown-watch cd shutdown-watch # Probe all sites in data/targets.txt python -m shutdownwatch scan \ --targets data/targets.txt \ --out results.json # Sample output: # wikipedia.org ok # pib.gov.in ok # blocked-site.com dns_tampering # overall: partial_blocking

2
Mesh Simulator

# Run with default settings (30 nodes) python -m shutdownwatch mesh # Customize the simulation python -m shutdownwatch mesh \ --nodes 50 \ --radius 20.0 \ --seed 42 # Sample result: # direct: 50% delivery, 72 step avg, 5 tx # epidemic: 100% delivery, 11 step avg, 290 tx

3
Run the Test Suite

python -m unittest discover -s tests -v
